# Latent — 習慣で写真を現像する

> **Latent（潜像）** … フィルムには写っているのに、現像するまで目に見えない像のこと。

写真を選んで目標を決めると、写真がグレーのタイルで覆われます。
1日達成するごとにタイルが1枚ずつ外れ、期限の日に写真がどこまで現れたかが、そのまま達成度になります。

- 目標はいくつでも追加できます（上限なし）
- 期限あり → 開始日から期限までの日数ぶんのタイル
- 期限なし → 365枚のタイル
- タイルは時系列順に、左上から順番に外れます
- 入力を忘れた日は、あとから日付を選んで記録できます
- 過ぎたのに開かなかった日のタイルは、そのまま写真の「穴」として残ります
- 完成すると演出が流れ、写真を画像として保存・共有できます

---

## 1. 公開する（GitHub Pages の場合）

PWAとしてホーム画面に追加するには、ファイルをネット上に置く必要があります。無料で一番手軽なのが GitHub Pages です。

1. GitHub にログインして、新しいリポジトリを作る（**Public** にする）
2. `Add file` → `Upload files` で、このフォルダの中身をすべてアップロードする
   - `index.html` がリポジトリの一番上の階層に来るようにしてください
   - `icons` フォルダは**フォルダごと**アップロードします（`icon` ではなく `icons`、末尾の s に注意）
3. `Commit changes` を押す
4. リポジトリの `Settings` → 左メニューの `Pages` を開く
5. **Source** を `Deploy from a branch`、**Branch** を `main` / `/(root)` にして `Save`
6. 1〜2分待つと、同じページに `https://ユーザー名.github.io/リポジトリ名/` のような URL が出ます

Netlify や Vercel を使う場合は、このフォルダをドラッグ&ドロップするだけで公開できます。

### 更新するとき

同じ名前のファイルをアップロードすれば上書きされます。削除してから上げ直す必要はありません。

**ただし、更新したら必ず `sw.js` の3行目にある `CACHE` の番号を上げてください。**
上げないと、オフライン用に保存された古いファイルが表示され続け、変更が反映されません。

## 2. ホーム画面に追加する

**iPhone（Safari）**
1. Safari で上の URL を開く
2. 下の共有ボタン（□に↑）→ `ホーム画面に追加`
3. アイコンから起動すると、アドレスバーのない全画面で開きます

**Android（Chrome）**
1. Chrome で URL を開く
2. 右上のメニュー → `アプリをインストール` または `ホーム画面に追加`

一度開いたあとはオフラインでも起動します。

## 3. 使い方

| したいこと | 操作 |
|---|---|
| 目標を追加する | 一覧の下の「目標を追加」 |
| 写真の使う範囲を選ぶ | 写真を選ぶと切り抜き画面が開く。あとから「切り抜きを調整する」でやり直せる |
| 今日を達成にする | 詳細画面の下のボタン |
| 別の日を記録する / 取り消す | 写真のタイルを直接タップ、または「記録を修正」 |
| 表示を切り替える | 一覧の右上のアイコン（写真 ⇄ 名前だけ） |
| 完成した写真を保存する | 詳細画面の下のボタン、または「⋮」→「いまの写真を保存・共有する」 |
| 演出をもう一度見る | 詳細画面の「⋮」→「タイルが外れる様子を見る」 |
| 目標を編集・削除する | 詳細画面の右上「⋮」 |
| 通知やバックアップの設定 | 一覧の右上「⋮」 |

### 一覧の2つの表示

右上のアイコンで切り替わります。選んだほうが記憶されます。

- **写真** … 切り抜いた写真をそのままの比率で並べます。進み具合が一目でわかります
- **名前だけ** … 目標名とバーだけの一覧。数が増えたときに見渡しやすくなります

### 進行中と棚

**期限が過ぎた目標**と、**期限前でも100%完成した目標**は、自動的に「棚」へ移ります。棚に何か入ると、一覧の上に切り替えが出ます。完成した写真がここに貯まっていきます。

### 詳細画面の見かた

- 大きな数字 = **完成度**（外したタイル ÷ 全タイル）
- バーの上のシアンの縦線 = 今日の位置。線より左にバーが届いていれば、ペースどおりです
- **これまでの達成率** = 外したタイル ÷ 経過日数
- シアンの枠がついたタイル = 今日のぶん

タイルの色は、写真の明るさに合わせて自動で決まります。暗い写真には明るめ、明るい写真には暗めのタイルが乗るので、どんな写真でも境目がはっきり見えます。

### 期間を変更したとき

期限や開始日を変えて、既にある記録が新しい期間の外に出る場合は、保存前に警告が出ます。

**記録は消えません。** 数えられなくなるだけで、期間を元に戻せばそのまま復活します。

## 4. 通知

設定（一覧の右上「⋮」）から調整できます。

- **ことばのトーン** … 淡々と / やさしい / 厳しめ の3種類
- **送る時間帯** … 朝・夕方・夜。それぞれ時刻を変えられます

その時点で**未記録の目標があるときだけ**送られます。朝のうちに記録すれば、夕方も夜も来ません。すべて記録した日は通知ゼロです。

目標が1つのときは、状況（連続している / 昨日を落とした / 完成まであと少し）に応じて文面が変わります。2つ以上のときは名前を出さず、残りの数だけを伝えます。

**「文面を確認する」**を押すと、いまの自分の状況で実際に出る文面を、3つのトーンで読み比べられます。

> **通知が実際に届くのはアプリ版（Capacitor）にしてからです。**
> ブラウザ版には時刻を指定して通知を予約する手段がないため、いまは設定と文面の確認だけができます。

### 文面を増やす・変える

`messages.js` を編集してください。ロジックとは切り離してあるので、この1ファイルだけで完結します。

トーン別・時間帯別・状況別に配列が並んでいるので、好きな場所に1行足せば候補に加わります。使える差し込み語はファイル先頭のコメントに書いてあります。

## 5. データとバックアップ

記録と写真は、この端末のブラウザの中（IndexedDB）だけに保存されます。サーバーには何も送られません。

そのため、次の場合はデータが消えます。

- ブラウザの「サイトデータを削除」をした
- 機種変更した
- iOS で、そのサイトを長期間開かなかった（Safari が自動で消すことがあります）

### いまできる備え

**「データを書き出す」で JSON ファイルを保存しておいてください。** 月に一度くらいが目安です。
iPhone なら、書き出したあと共有先に「ファイル」を選ぶと iCloud Drive に置けます。
新しい端末では「データを読み込む」で、写真も設定もそのまま復元できます。

### バックアップ欄について

設定の「今すぐバックアップ」「バックアップから書き戻す」は、**アプリ版で自動化される仕組みの動作確認用**です。

アプリ版では、記録を変更するたびに端末の書類フォルダへ自動保存され、そのファイルは iCloud のバックアップに含まれます。機種変更して復元すれば、何もしなくても記録が戻ります。

記録が空の状態で起動したときにバックアップが残っていれば、書き戻すかどうかを尋ねます。

## 6. ファイルの中身

```
index.html              画面の構造
styles.css              見た目
app.js                  ロジック（保存・タイル計算・記録・通知・バックアップ）
messages.js             通知の文面データ
manifest.webmanifest    アプリ名やアイコンの定義
sw.js                   オフライン用のキャッシュ
icons/                  ホーム画面のアイコン（4ファイル）
```

### アプリ版にするときの差し替え箇所

`app.js` に、端末に依存する処理を2箇所だけ切り出してあります。Capacitor 化したら、中身をコメントに書いてある内容へ置き換えるだけで動きます。

| 場所 | 役割 | 差し替える中身 |
|---|---|---|
| `backup` の `save` / `load` / `info` | 記録の自動バックアップ | `@capacitor/filesystem` で `Directory.Documents` に読み書き |
| `notifier.schedule` | 通知の予約 | `@capacitor/local-notifications` に `buildPlan()` の結果を渡す |

`Directory.Documents` に置いたファイルは iCloud のバックアップに自動的に含まれるため、機種変更しても記録が戻ります。

バックアップの中身を作る `serializeAll()`、書き戻す `restoreAll()`、通知の文面を決める `pickLine()`、予約内容を組み立てる `buildPlan()` は端末に依存しないので、そのまま使えます。

`isNative()` が Capacitor 上かどうかを判定していて、両方の実装がこれで切り替わります。

### 手を入れるときのメモ

- 期限なしのときのタイル数は `app.js` の `DEFAULT_SPAN`（初期値 365）
- 期間の上限は `MAX_SPAN`（初期値 3650日 = 10年）
- 保存する写真の最大辺は `MAX_EDGE`（初期値 1400px）
- 完成演出の長さは `REVEAL_MS`（初期値 2200ミリ秒）
- 色は `styles.css` の先頭 `:root` にまとめてあります
- タイルの色を決める式は `app.js` の `tileColors()`
- **ファイルを更新したら `sw.js` の `CACHE = 'latent-v10'` の番号を上げてください**

### タイルの並べ方について

写真の縦横比から、タイルがなるべく正方形になる列数を選びます。割り切れないぶんは「1枚少ない行」を全体に散らして吸収するので、どんな日数でも写真がぴったり覆われます。

タイルの境界はピクセル単位に丸めて、隣り合うタイルが必ず同じ座標を共有するようにしてあります。これにより、どんな画面幅でも隙間が出ません。

### 保存データの構造

IndexedDB に2つの置き場所があります。

- `goals` … 目標ごとの記録（`id` / `title` / `start` / `end` / `done` / `photo` / `pw` / `ph` / `lum` / `celebrated`）
- `prefs` … 通知のトーンと時間帯、一覧の表示モード、動作確認用のバックアップ

`done` は達成した日付の配列です。期間の外にある日付も消さずに残していて、数えるときに範囲で絞っています。

内部名が `mosaic-db` のままなのは、名前を変えると既存の記録が読めなくなるためです。表示には出てきません。
